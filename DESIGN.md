# Enamel design context

Enamel is a product interface for preparing an award on a laptop in ordinary
daylight, often shortly before a team event. Keep the fleet's existing dark
shell and orange action color; use a quiet preview surface so both light paper
and colored enamel remain easy to judge. Tokens, header, footer and auth come
from Neorgon's shared kits.

The artifact deserves more visual emphasis than the controls. Certificates use
the available stage width; badges retain their compact square scale. Treat a
certificate as a printed sheet, with readable margins, a deliberate hierarchy,
fine rules and a restrained background. Use expressive fonts on the artifact
and the system UI face on controls. Preserve a preset's authored typography
until the user explicitly selects a different font pairing.

Offer finished designs, visual silhouette and symbol pickers, and short useful
descriptions. Keep library filters and reusable local presets beside the
existing preset workflow. Selected controls use an outline and explicit state,
not color alone. All controls work with a keyboard and at phone widths.

Artifact colors remain six-digit hex because that is the persisted design
schema. New interface colors should use existing fleet tokens. Vector elements
belong to the canonical Insignia Kit and are synced into Enamel and Sash. Keep
provenance and verification in the same renderer as the artwork.
